[C1] Plaintext Credentials Persisted to Database
────────────────────────────────────────────────
Severity: CRITICAL
Impact: Data breach, GDPR/CCPA violation, credential exposure
Status: ✗ UNFIXED

Files Affected:
  • /Users/max/Zima/backend/app/providers/breach/dehashed/client.py:65
  • /Users/max/Zima/backend/app/modules/identity/breach_monitor/service.py:122

Problem:
  DeHashed API returns plaintext passwords in response entries array.
  Provider stores full entries array in evidence dict.
  Signal evidence dict is persisted to PostgreSQL database.
  Attackers with database access get all plaintext credentials.

Example Vulnerable Code:
  ```python
  # Provider returns:
  raw={"entries": [
    {"email": "user@example.com", "password": "MyPassword123"},
    ...
  ]}

  # Module stores entire finding in DB:
  evidence={"raw_finding": finding}  # ← Contains plaintext passwords
  ```

Fix Time: 1.5 hours
See: REMEDIATION_GUIDE_WAVE1.md - Fix 1


[C2] Subprocess Injection in Holehe & Maigret Providers
────────────────────────────────────────────────────────
Severity: CRITICAL
Impact: Remote Code Execution (mitigated by list-based subprocess),
        Denial of Service, Information Disclosure
Status: ✗ UNFIXED

Files Affected:
  • /Users/max/Zima/backend/app/providers/tools/holehe/client.py:75
  • /Users/max/Zima/backend/app/providers/tools/maigret/client.py:80-88
  • /Users/max/Zima/backend/app/modules/identity/username_exposure/service.py:114

Problem:
  User-supplied email/username passed to subprocess without validation:
    - No format validation (any string accepted)
    - No length checks (100MB strings possible, exhausts memory)
    - No character validation (control chars might trigger tool bugs)

Attack Scenarios:
  1. Memory DoS: 100MB email address → process OOM kill
  2. CPU DoS: Specially crafted username → infinite tool processing loop
  3. Info disclosure: Tool errors reveal system paths/versions

Vulnerable Code:
  ```python
  # holehe/client.py line 75
  cmd = [_TOOL_NAME, "--only-used", "--no-color", email]
  # No validation - could be 1GB string or contain special bytes

  # maigret/client.py line 82
  cmd = [_TOOL_NAME, username, ...]
  # No validation of username format or length
  ```

Fix Time: 1 hour
See: REMEDIATION_GUIDE_WAVE1.md - Fix 2


[C3] Uncontrolled External API Calls Without Rate Limiting
──────────────────────────────────────────────────────────
Severity: CRITICAL
Impact: Financial damage ($100s-$1000s), DoS, Quota exhaustion
Status: ✗ UNFIXED

Affected Providers:
  • HIBP (rate limited but no backpressure)
  • DeHashed ($0.10/query, ~$700 for 1000 email scan)
  • BreachDirectory (RapidAPI quota shared)
  • Hudson Rock ($0.05/query, expensive)
  • LeakCheck (free, but quota possible)
  • Epieos ($0.10/query)
  • EmailRep (free tier rate limited)

Problem:
  No authentication required to trigger API calls
  No quota enforcement per user/tier
  Attacker registers account, scans 1000 emails, racks up $700 DeHashed bill
  No cost attribution - unclear who authorized spending

Fix Time: 3 hours
See: REMEDIATION_GUIDE_WAVE1.md - Fix 3

[M2] Sensitive PII in Evidence Dicts (Epieos)
──────────────────────────────────────────────
Severity: MEDIUM
Status: ✗ UNFIXED

Files Affected:
  • /Users/max/Zima/backend/app/providers/social/epieos/client.py:90-99, 116-119
  • /Users/max/Zima/backend/app/modules/identity/alias_correlation/service.py:72

Problem:
  Provider returns real names, activity timestamps, YouTube links in evidence
  Module stores real names as "alias_name" in evidence
  These become PII in signals database (GDPR scope creep)
  Attacker with database access gets full identity map

Example:
  ```python
  raw={
    "name": "John Smith",  # ← PII
    "youtubeChannel": "...",  # ← Identity link
    "lastActivity": "2026-03-27T10:30:00Z",  # ← Behavioral data
  }
  ```

Fix Time: 0.5 hours
See: REMEDIATION_GUIDE_WAVE1.md - Fix 5
